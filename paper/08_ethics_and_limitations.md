# 伦理与局限性

## 潜在风险

- 开放探索可能主动触发删除、发送、提交、授权、交易等高影响或不可逆操作。
- 对真实网站的自动交互可能影响账号数据、其他用户、服务资源或网站正常运行。
- 页面内容、执行轨迹和截图可能包含个人信息、凭据或其他敏感数据。
- VLM 的风险判断可能漏报危险操作，也可能误报并过早终止探索。
- 错误或过期的功能模型若被下游规划器采用，可能导致不当操作。

## 局限性与失败案例

- 模型只覆盖探索中被观察和交互到的功能，不保证完整功能发现。
- 当前主要表达位置约束和已观察到的直接动作依赖，不恢复完整业务状态、严格 precondition 或隐藏因果逻辑。
- semantic location、function hypothesis 与 risk judgment 仍依赖 VLM，可能发生误判。
- executor failure 与环境不支持仍可能混淆。
- 风险判断或 commit boundary 前停止可能降低覆盖；Partially Supported 不能等同于完整功能确认。
- 动态网站可能使已有知识失效，需要知识更新和重新验证机制。
- 证据可追溯提升可审查性，但不构成形式化正确性或完整安全审计保证。

## 缓解措施

- 优先在受控、可重置、获得授权的测试环境和隔离账号中开展实验。
- 按影响程度与可恢复性控制验证深度，在不可逆 commit boundary 前停止。
- 显式区分 Proposed、Partially Supported、Interaction-Supported、Failed 和 Incomplete，保守限制下游可用知识。
- 保存 hypothesis source、execution trace、before/after observations 和 outcome judgment，支持人工检查。
- 对敏感数据进行最小化收集、脱敏、受限保存与投稿前清理。
- 记录失败、不确定、风险误判和过早停止案例，不只报告成功轨迹。
- 遵守目标网站条款、访问控制和研究伦理要求；具体实验审批与数据治理方案待数据集确定后补充。

## 未来工作（不作为当前贡献）

- 功能测试与回归测试；
- 自动任务构造；
- 更完整的自动化执行；
- 动态环境中的知识失效检测与重新验证。
